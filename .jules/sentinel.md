## 2025-03-08 - [Bypass in handoff endpoint missing secret parameter validation]
**Vulnerability:** In `src/endpoints/handoff.ts`, the secret validation block evaluated `if (expectedSecret && secret != null)`. This meant an attacker could omit the `secret` parameter (making it `null` or `undefined`) to evaluate to false and completely bypass the authorization check.
**Learning:** `if (expectedSecret && secret != null)` bypasses security logic completely when `secret` is omitted. It's a common logical flaw when trying to check both if a secret is expected and if the received secret is valid.
**Prevention:** If an `expectedSecret` is configured, immediately require the `secret` parameter (e.g. return 403 if missing). Alternatively, use `if (expectedSecret)` and then evaluate `if (secret == null) { return forbidden }`.
